## MCAP ファイルレイアウト

MCAPファイルの基本的な構造は以下の通りです。

```
<マジックナンバー>
<ヘッダー>
<データセクション>
[<サマリーセクション>]
[<サマリーオフセットセクション>]
<フッター>
<マジックナンバー>
```

*   `サマリーセクション`と`サマリーオフセットセクション`は任意です。
*   ファイルがこの構造に従っていない場合、不正な形式と見なされます。

### マジックナンバー

MCAPファイルは、必ず特定の8バイトのシーケンスで開始および終了する必要があります。

```
0x89, M, C, A, P, 0x30, \r, \n
```

*   `MCAP`に続くバイト (`0x30`) はメジャーバージョンを示します。

### 主要セクション

#### ヘッダー (Header)

*   **役割:** ファイルの先頭（先頭のマジックナンバーの直後）に配置される最初のレコードです。
*   **内容:** プロファイル情報（例: `ros2`）や、書き込みに使用されたライブラリの情報などが含まれます。

#### データセクション (Data Section)

*   **役割:** メッセージデータ本体と、それをサポートするレコードを格納します。
*   **内容:** `Schema`（スキーマ定義）、`Channel`（トピックとエンコーディング情報）、`Message`（実際のメッセージデータ）などのレコードが含まれます。
*   **特徴:**
    *   レコードは直接書き込むことも、`Chunk`レコード内にまとめて圧縮・インデックス化することも可能です。
    *   セクションの最後は必ず`Data End`レコードでなければなりません。

#### サマリーセクション (Summary Section)

*   **役割:** ファイル情報やデータセクション内のレコードへの高速なルックアップを可能にするための、インデックス情報を格納する任意のセクションです。
*   **内容:** `Chunk Index`（Chunkの位置情報）、`Attachment Index`（添付ファイルの位置情報）、`Metadata Index`（メタデータの位置情報）、`Statistics`（統計情報）などが含まれます。
*   データセクション内の`Schema`や`Channel`レコードの複製もここに配置され、高速なアクセスを助けます。

#### フッター (Footer)

*   **役割:** ファイルの末尾（末尾のマジックナンバーの直前）に配置される最後のレコードです。
*   **内容:** サマリーセクションやサマリーオフセットセクションへのバイトオフセット、およびサマリーセクション全体のCRC32チェックサムを含みます。これにより、リーダーはファイルのインデックス情報を効率的に読み取ることができます。
