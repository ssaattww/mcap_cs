# C# MCAPライブラリ移植 開発計画書

## 1. プロジェクト概要

本プロジェクトは、既存のC++ MCAPライブラリをC#へ移植することを目的とします。C#で開発されたアプリケーション、特に .NET環境で動作するロボット工学やデータロギングシステムにおいて、MCAPフォーマットのデータをネイティブに扱えるようにすることを目指します。

## 2. 移植スコープ

C++版の主要な機能をすべてC#に移植します。

- **データモデル**: MCAPフォーマットの全レコードタイプに対応するクラスまたは構造体を定義します。
- **書き込み機能 (`McapWriter`)**:
    - ファイルおよびストリームへの書き込み
    - スキーマとチャンネルの登録
    - メッセージ、アタッチメント、メタデータの書き込み
    - チャンク化と圧縮 (Zstd, LZ4)
    - インデックス生成 (メッセージ、チャンク等)
    - CRCチェック
- **読み込み機能 (`McapReader`)**:
    - ファイルおよびストリームからの読み込み
    - サマリー解析による高速なランダムアクセス
    - メッセージのイテレーション (時間範囲・トピックフィルタリング機能を含む)
    - ヘッダー、フッター、統計情報などへのアクセス
    - 圧縮チャンクの自動伸長
- **低レベルインターフェース**: C#のイディオムに合わせたインターフェース (`Stream`, `IDisposable`等) を設計し、拡張性を確保します。

## 3. 開発アプローチ (TDD)

テスト駆動開発（TDD）アプローチを採用します。

1.  **テスト先行**: C++版の既存テストや仕様を参考に、C#で対応するテストケースを先に作成します。まずは失敗するテストを記述します。
2.  **実装**: 失敗したテストをパスするための最小限のコードを実装します。
3.  **リファクタリング**: テストが通る状態を維持しながら、コードの品質を向上させます。
4.  **コミット**: 各機能のテストと実装が完了した段階で、意味のある単位でコミットします。

このサイクルを繰り返すことで、品質の高いライブラリを効率的に開発します。

## 4. 開発フェーズとタスク分割

### フェーズ1: プロジェクトセットアップと基本データモデルの実装

-   **タスク 1.1**: C# プロジェクトの作成
    -   `dotnet new classlib` を使用して、`Mcap.CSharp` のような名前のクラスライブラリプロジェクトを作成します。
    -   ソリューションファイルを作成し、プロジェクトを追加します。
    -   xUnit または NUnit を用いたテストプロジェクトをセットアップします。
-   **タスク 1.2**: 基本的な型と定数の定義
    -   `OpCode`, `Compression` などの列挙型を定義します。
    -   `Status`, `MessageView` などの基本的な構造体/クラスを定義します。
-   **タスク 1.3**: データモデルのクラス実装
    -   `Header`, `Footer`, `Schema`, `Channel`, `Message` など、MCAPの各レコードに対応するC#クラスを実装します。
    -   これらのクラスのシリアライズ/デシリアライズのロジックは、この段階ではプレースホルダーとします。

### フェーズ2: 書き込み機能 (McapWriter) の実装

-   **タスク 2.1**: `IWritable` に相当するインターフェースの設計
    -   C#の `System.IO.Stream` を活用した書き込みインターフェースを設計します。
-   **タスク 2.2**: `McapWriter` クラスの実装 (コアロジック)
    -   `addSchema`, `addChannel`, `write(Message)` などのメソッドの骨格を実装します。
    -   まずは圧縮なし、チャンク化なしの単純な書き込み機能から実装します。
-   **タスク 2.3**: シリアライズロジックの実装
    -   各データモデルクラスをMCAP仕様に従ってバイト配列に変換するロジックを実装します。
-   **タスク 2.4**: チャンク化機能の実装
    -   `McapWriterOptions` に基づいて、メッセージをチャンクにまとめて書き込む機能を実装します。
-   **タスク 2.5**: 圧縮機能の実装
    -   ZstdおよびLZ4の.NETラッパーライブラリ（例: `ZstdNet`, `lz4net`）を導入します。
    -   チャンクを圧縮して書き込む機能を実装します。
-   **タスク 2.6**: インデックス生成とサマリー書き込み機能の実装
    -   書き込みの最後に、各種インデックスとサマリーセクションを生成してファイル末尾に書き込む機能を実装します。

### フェーズ3: 読み込み機能 (McapReader) の実装

-   **タスク 3.1**: `IReadable` に相当するインターフェースの設計
    -   `System.IO.Stream` を活用した読み込みインターフェースを設計します。
-   **タスク 3.2**: `McapReader` クラスの実装 (コアロジック)
    -   ファイルを開き、ヘッダーとフッターを読み込む機能を実装します。
-   **タスク 3.3**: デシリアライズロジックの実装
    -   バイト配列から各データモデルクラスに変換するロジックを実装します。
-   **タスク 3.4**: サマリー解析機能の実装
    -   `readSummary()` を実装し、インデックス情報をメモリにロードする機能を実装します。
-   **タスク 3.5**: 圧縮解除機能の実装
    -   圧縮されたチャンクを自動的に伸長する機能を実装します。
-   **タスク 3.6**: メッセージ読み込みとイテレーション機能の実装
    -   `readMessages()` を実装し、`IEnumerable<MessageView>` を返すようにします。
    -   LINQを活用して、時間範囲フィルタ (`.Where(m => m.LogTime >= start && m.LogTime <= end)`) やトピックフィルタ (`.Where(m => topics.Contains(m.Channel.Topic))`) を実現します。

### フェーズ4: 適合性テストとドキュメント作成

-   **タスク 4.1**: 適合性テストの実施
    -   プロジェクトルートの `tests/conformance` にあるテストスイートを使用して、C#実装がMCAP仕様に準拠していることを確認します。
    -   必要に応じて、C#からテストスイートを実行するためのスクリプトやテストハーネスを作成します。
-   **タスク 4.2**: APIドキュメントの作成
    -   `DocFX` や `Sandcastle` などのツールを使用して、公開APIのドキュメントを生成します。
    -   主要なクラスやメソッドには、XMLドキュメントコメントを記述します。
-   **タスク 4.3**: READMEとサンプルコードの作成
    -   C#ライブラリの使い方を示す `README.md` を作成します。
    -   基本的な読み書きの方法を示す簡単なサンプルコードを提供します。

## 7. 想定されるリスクと対策

-   **リスク**: C++の低レベルなポインタ操作やメモリ管理のロジックを、安全なC#コードに変換する際の複雑さ。
    -   **対策**: C#の `Stream` や `Span<T>`, `Memory<T>` を活用し、パフォーマンスを維持しつつ安全なコードを記述する。必要な場合は `unsafe` コンテキストの使用を検討するが、最小限に留める。
-   **リスク**: 外部圧縮ライブラリの.NETラッパーに起因する問題（パフォーマンス、バグなど）。
    -   **対策**: 複数のラッパーライブラリを評価・選定する。事前に簡単なベンチマークテストを実施する。
-   **リスク**: TDDに不慣れな場合の開発速度の低下。
    -   **対策**: シンプルな機能から始め、徐々にTDDのサイクルに慣れていく。ペアプログラミングなどを活用して知識を共有する。

## 8. 開発環境

-   **.NET SDK**: .NET 8.0 を使用。
-   **IDE**: Visual Studio 2022 (Windows/macOS) または Visual Studio Code (C# Dev Kit拡張機能付き) を推奨。
-   **テストフレームワーク**: xUnit を使用。
-   **ビルドツール**: `dotnet CLI` を使用。
